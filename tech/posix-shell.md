# POSIX shell: the `gradlew` script

## What it is

A **shell** is a program that reads the commands you type and runs them. **POSIX** is the standard that says what a basic shell on macOS and Linux must understand; `/bin/sh` is the name of that shell. A **shell script** is a text file of such commands, run top to bottom. The first line, `#!/bin/sh`, is the **shebang**: it tells the operating system which program should run the file. Everything after a `#` on a line is a comment that the shell ignores.

A **variable** holds text. You set it with `name=value` (no spaces around `=`) and read it with `$name`. An **environment variable** is a variable the shell hands to every program it starts, for example `JAVA_HOME`. An **exit code** is the number a program returns when it finishes: 0 means success, anything else means failure. The shell keeps the last one in `$?`.

## Why this repository uses it

`gradlew` is the file you actually type. Its whole job is to find Java and start the wrapper jar (`gradle-wrapper.md`) with your arguments, on any Unix-like system, with no other tool installed. Understanding it explains what happens in the first 50 milliseconds of every build, and why the file needs to be executable, saved with Unix line endings and written for plain `sh`.

## How it works underneath

1. The shell reads `gradlew` one command at a time and runs each.
2. Special characters matter. `$` expands a variable, `"..."` groups text into one word while still expanding variables, `'...'` groups text with no expansion at all, `\` makes the next character ordinary.
3. `$0` is how the script was called, `$@` is the list of all arguments, `$*` the same as one string, `$#` how many there are.
4. `cmd1 && cmd2` runs `cmd2` only if `cmd1` succeeded. `cmd1 || cmd2` runs `cmd2` only if `cmd1` failed. `a | b` feeds the output of `a` into `b` (a **pipe**). `>file` writes output to a file, `2>&1` sends error output to the same place as normal output, `>&2` sends output to the error stream, `/dev/null` is a file that throws everything away.
5. `$( ... )` runs the command inside and substitutes its output.
6. At the end, `exec` replaces the script's own process with Java. The shell is gone and Java's exit code becomes the script's exit code.

This script avoids everything outside POSIX: no arrays, no `[[ ]]`, no Bash-only features. The notes in lines 21 to 65 say why.

## Walkthrough of this repository's use

The licence block and the long comment in lines 1 to 65 are comments only. The code starts at line 67. Comments inside the quoted blocks are explained where they carry meaning.

### Finding the folder the script lives in (lines 67 to 83)

```sh
# Attempt to set APP_HOME

# Resolve links: $0 may be a link
app_path=$0

# Need this for daisy-chained symlinks.
while
    APP_HOME=${app_path%"${app_path##*/}"}  # leaves a trailing /; empty if no leading path
    [ -h "$app_path" ]
do
    ls=$( ls -ld "$app_path" )
    link=${ls#*' -> '}
    case $link in             #(
      /*)   app_path=$link ;; #(
      *)    app_path=$APP_HOME$link ;;
    esac
done
```

- `app_path=$0` stores how the script was invoked, for example `./gradlew`.
- `while ... do ... done` repeats. Between `while` and `do` there are two commands, and the loop continues while the last one succeeds.
- `APP_HOME=${app_path%"${app_path##*/}"}` is variable surgery. `${app_path##*/}` removes the longest start of the text that ends in `/`, which leaves just the file name (`gradlew`). `${app_path%"gradlew"}` then removes that file name from the end, which leaves the folder part with its trailing slash (`./`). If there is no slash, the result is empty. This is **parameter expansion**, a built-in way to cut text without starting another program.
- `[ -h "$app_path" ]` is the `test` command: it succeeds if the path is a symbolic link (a file that points to another file). The quotes keep a path with spaces as one word.
- `ls=$( ls -ld "$app_path" )` runs `ls` and stores its output. For a link the output ends in `name -> target`.
- `link=${ls#*' -> '}` removes the shortest start of the text that ends in ` -> `, which leaves the target.
- `case $link in ... esac` compares the text with patterns. `/*)` matches an absolute path, so the link target is used as is. `*)` matches anything else (a relative target), so the folder part is put in front. `;;` ends each branch. The `#(` is a comment that only helps editors.
- Why loop? A link can point to a link that points to a link ("daisy-chained"). The loop follows them until it reaches the real file. When `gradlew` is a normal file, the loop body never runs.

### Names and the real folder (lines 85 to 89)

```sh
# This is normally unused
# shellcheck disable=SC2034
APP_BASE_NAME=${0##*/}
# Discard cd standard output in case $CDPATH is set (https://github.com/gradle/gradle/issues/25036)
APP_HOME=$( cd -P "${APP_HOME:-./}" > /dev/null && printf '%s\n' "$PWD" ) || exit
```

- `APP_BASE_NAME=${0##*/}` is the script's file name (`gradlew`). It is passed to Gradle as the program name in messages.
- `APP_HOME=$( cd -P "${APP_HOME:-./}" > /dev/null && printf '%s\n' "$PWD" ) || exit` goes into the folder and asks where it really is. `${APP_HOME:-./}` means "the value of `APP_HOME`, or `./` if it is empty". `cd -P` changes folder and resolves links to the physical path. `> /dev/null` throws away anything `cd` prints (it can print when `CDPATH` is set). `&& printf '%s\n' "$PWD"` prints the new current folder, and `$( ... )` captures it. `|| exit` ends the script if any of that failed, with the failure's exit code.

### Memory limit setting (lines 91 to 92)

```sh
# Use the maximum available, or set MAX_FD != -1 to use that value.
MAX_FD=maximum
```

`MAX_FD=maximum` sets a variable that later decides how many files the process may keep open. FD stands for file descriptor, the number the operating system gives to an open file or connection.

### Two helper functions (lines 94 to 103)

```sh
warn () {
    echo "$*"
} >&2

die () {
    echo
    echo "$*"
    echo
    exit 1
} >&2
```

A **function** is a named group of commands you can call like a program.
- `warn` prints its arguments. `"$*"` joins all arguments with spaces into one string. The `} >&2` after the closing brace redirects everything the function prints to the error stream, so warnings do not mix with normal output.
- `die` prints an empty line, the message, another empty line, and then `exit 1`, which ends the script with failure code 1. Its output also goes to the error stream.

### Detecting the operating system (lines 105 to 115)

```sh
# OS specific support (must be 'true' or 'false').
cygwin=false
msys=false
darwin=false
nonstop=false
case "$( uname )" in                #(
  CYGWIN* )         cygwin=true  ;; #(
  Darwin* )         darwin=true  ;; #(
  MSYS* | MINGW* )  msys=true    ;; #(
  NONSTOP* )        nonstop=true ;;
esac
```

- Four variables are set to the **words** `false`. They are used later as commands: `true` and `false` are real programs that succeed and fail, so `if "$darwin"` reads naturally.
- `case "$( uname )" in` runs `uname`, which prints the operating system's name (`Darwin` on a Mac), and compares it with patterns. `CYGWIN*` matches any text that starts with CYGWIN. `MSYS* | MINGW*` matches either. Each match sets one variable to `true`. On this machine `darwin` becomes `true`.

### Finding Java (lines 119 to 142)

```sh
# Determine the Java command to use to start the JVM.
if [ -n "$JAVA_HOME" ] ; then
    if [ -x "$JAVA_HOME/jre/sh/java" ] ; then
        # IBM's JDK on AIX uses strange locations for the executables
        JAVACMD=$JAVA_HOME/jre/sh/java
    else
        JAVACMD=$JAVA_HOME/bin/java
    fi
    if [ ! -x "$JAVACMD" ] ; then
        die "ERROR: JAVA_HOME is set to an invalid directory: $JAVA_HOME

Please set the JAVA_HOME variable in your environment to match the
location of your Java installation."
    fi
else
    JAVACMD=java
    if ! command -v java >/dev/null 2>&1
    then
        die "ERROR: JAVA_HOME is not set and no 'java' command could be found in your PATH.

Please set the JAVA_HOME variable in your environment to match the
location of your Java installation."
    fi
fi
```

- `[ -n "$JAVA_HOME" ]` succeeds if the variable is not empty. `JAVA_HOME` is the folder of an installed JDK.
- `[ -x "$JAVA_HOME/jre/sh/java" ]` succeeds if that file exists and may be run. That odd path exists only in an old IBM JDK on AIX, so it is checked first. Otherwise `JAVACMD=$JAVA_HOME/bin/java` is the normal location.
- `[ ! -x "$JAVACMD" ]` (the `!` negates) catches a `JAVA_HOME` that points to a place with no runnable `java`. Then `die` prints the error and the script stops with code 1. The message spans several lines because the quotes stay open until the closing `"`.
- If `JAVA_HOME` is empty, `JAVACMD=java` means "look for `java` in the folders of the `PATH` variable". `command -v java` prints where the shell would find it, and `>/dev/null 2>&1` hides both its output and its errors. `!` negates, so the `then` branch runs when `java` is not found, and `die` reports it.
- `fi` ends an `if`, in the same way `esac` ends a `case` and `done` ends a loop.

### Raising the open-file limit (lines 144 to 161)

```sh
# Increase the maximum file descriptors if we can.
if ! "$cygwin" && ! "$darwin" && ! "$nonstop" ; then
    case $MAX_FD in #(
      max*)
        # In POSIX sh, ulimit -H is undefined. That's why the result is checked to see if it worked.
        # shellcheck disable=SC2039,SC3045
        MAX_FD=$( ulimit -H -n ) ||
            warn "Could not query maximum file descriptor limit"
    esac
    case $MAX_FD in  #(
      '' | soft) :;; #(
      *)
        # In POSIX sh, ulimit -n is undefined. That's why the result is checked to see if it worked.
        # shellcheck disable=SC2039,SC3045
        ulimit -n "$MAX_FD" ||
            warn "Could not set maximum file descriptor limit to $MAX_FD"
    esac
fi
```

- `if ! "$cygwin" && ! "$darwin" && ! "$nonstop"` runs the block only if none of those three is `true`. **On macOS `darwin` is `true`, so this whole block is skipped.** It matters on Linux.
- `case $MAX_FD in max*)` matches the value `maximum`. `MAX_FD=$( ulimit -H -n ) || warn "..."` asks for the hard limit of open files (`ulimit -H -n`) and stores the number; if that command fails, `warn` prints a message and the script goes on. The comment explains that POSIX does not define these `ulimit` options, so the result must be checked.
- The second `case` matches `''` (empty) or `soft` and does nothing: `:` is the "do nothing, succeed" command. Any other value, a number, goes to `ulimit -n "$MAX_FD"`, which raises the limit for this process; a failure only prints a warning. A Gradle build opens many files, so a low limit would break it.

### Windows-like shells (lines 163 to 199)

```sh
# Collect all arguments for the java command, stacking in reverse order:
#   * args from the command line
#   * the main class name
#   * -classpath
#   * -D...appname settings
#   * --module-path (only if needed)
#   * DEFAULT_JVM_OPTS, JAVA_OPTS, and GRADLE_OPTS environment variables.

# For Cygwin or MSYS, switch paths to Windows format before running java
if "$cygwin" || "$msys" ; then
    APP_HOME=$( cygpath --path --mixed "$APP_HOME" )

    JAVACMD=$( cygpath --unix "$JAVACMD" )

    # Now convert the arguments - kludge to limit ourselves to /bin/sh
    for arg do
        if
            case $arg in                                #(
              -*)   false ;;                            # don't mess with options #(
              /?*)  t=${arg#/} t=/${t%%/*}              # looks like a POSIX filepath
                    [ -e "$t" ] ;;                      #(
              *)    false ;;
            esac
        then
            arg=$( cygpath --path --ignore --mixed "$arg" )
        fi
        # Roll the args list around exactly as many times as the number of
        # args, so each arg winds up back in the position where it started, but
        # possibly modified.
        #
        # NB: a `for` loop captures its iteration list before it begins, so
        # changing the positional parameters here affects neither the number of
        # iterations, nor the values presented in `arg`.
        shift                   # remove old arg
        set -- "$@" "$arg"      # push replacement arg
    done
fi
```

This block runs only under Cygwin or MSYS, which are Unix-like environments on Windows (skipped on macOS).
- `"$cygwin" || "$msys"` is true if either variable holds `true`.
- `cygpath` converts between Unix and Windows paths. `--path --mixed` makes `APP_HOME` a Windows path with forward slashes. `--unix` makes `JAVACMD` a Unix path.
- `for arg do ... done` loops over each argument (`$@`). Inside, an inner `case` decides whether the argument is a file path: arguments that start with `-` are options and are left alone (`false`); arguments that look like an absolute path whose first folder exists (`/?*)` ... `[ -e "$t" ]`) are converted with `cygpath`; everything else is left alone. `t=${arg#/} t=/${t%%/*}` cuts the first folder name out of the path.
- `shift` drops the first argument, and `set -- "$@" "$arg"` appends the (possibly changed) argument at the end. Doing this once per argument rotates the whole list back to its original order. `set --` replaces the list of positional parameters (`$1`, `$2`, ...) and `--` marks that no option follows.

### Default Java options (lines 202 to 203)

```sh
# Add default JVM options here. You can also use JAVA_OPTS and GRADLE_OPTS to pass JVM options to this script.
DEFAULT_JVM_OPTS='"-Xmx64m" "-Xms64m"'
```

`DEFAULT_JVM_OPTS` holds two options for the wrapper's own Java process: `-Xmx64m` caps its memory at 64 megabytes and `-Xms64m` starts it at 64 megabytes. Only the small wrapper runs here; Gradle itself gets its own settings. The inner double quotes inside the single quotes are intended: later code reads them as quoted words.

### Building the final argument list (lines 205 to 214)

```sh
# Collect all arguments for the java command:
#   * DEFAULT_JVM_OPTS, JAVA_OPTS, and optsEnvironmentVar are not allowed to contain shell fragments,
#     and any embedded shellness will be escaped.
#   * For example: A user cannot expect ${Hostname} to be expanded, as it is an environment variable and will be
#     treated as '${Hostname}' itself on the command line.

set -- \
        "-Dorg.gradle.appname=$APP_BASE_NAME" \
        -jar "$APP_HOME/gradle/wrapper/gradle-wrapper.jar" \
        "$@"
```

`set --` replaces the positional parameters with a new list. The backslash at the end of a line continues the command on the next line. The new list is: `-Dorg.gradle.appname=gradlew` (a Java system property that Gradle uses as the program name), `-jar`, the full path of the wrapper jar built from `APP_HOME`, and then `"$@"`, the arguments you typed (`check`, `--args=...`). Because `"$@"` is quoted, each of your arguments stays one word even if it contains spaces.

### Making sure `xargs` exists (lines 216 to 220)

if ! command -v xargs >/dev/null 2>&1

The next step needs `xargs`, a program that splits text into words while honoring quotes. If `command -v xargs` finds nothing, `die` stops the script.

### Adding the option variables, safely (lines 222 to 246)

```sh
# Use "xargs" to parse quoted args.
#
# With -n1 it outputs one arg per line, with the quotes and backslashes removed.
#
# In Bash we could simply go:
#
#   readarray ARGS < <( xargs -n1 <<<"$var" ) &&
#   set -- "${ARGS[@]}" "$@"
#
# but POSIX shell has neither arrays nor command substitution, so instead we
# post-process each arg (as a line of input to sed) to backslash-escape any
# character that might be a shell metacharacter, then use eval to reverse
# that process (while maintaining the separation between arguments), and wrap
# the whole thing up as a single "set" statement.
#
# This will of course break if any of these variables contains a newline or
# an unmatched quote.
#

eval "set -- $(
        printf '%s\n' "$DEFAULT_JVM_OPTS $JAVA_OPTS $GRADLE_OPTS" |
        xargs -n1 |
        sed ' s~[^-[:alnum:]+,./:=@_]~\\&~g; ' |
        tr '\n' ' '
    )" '"$@"'
```

This is the hardest part of the script. The goal: take the options from `DEFAULT_JVM_OPTS`, `JAVA_OPTS` and `GRADLE_OPTS` (all empty except the first on a normal machine), put them in front of the argument list, and never let a stray character turn into a shell command.
- `printf '%s\n' "$DEFAULT_JVM_OPTS $JAVA_OPTS $GRADLE_OPTS"` prints the three variables on one line.
- `| xargs -n1` reads that line and prints one word per line, removing the quotes and backslashes. With the default it prints `-Xmx64m` and `-Xms64m` on separate lines.
- `| sed ' s~[^-[:alnum:]+,./:=@_]~\\&~g; '` puts a backslash in front of every character that is not a letter, digit or one of `- + , . / : = @ _`. `sed` is a stream editor; `s~a~b~g` replaces every match of `a` with `b`; `~` is used as the divider; `&` stands for the matched character. Now no character can act as a shell command.
- `| tr '\n' ' '` turns the line breaks into spaces.
- `eval "set -- $( ... )" '"$@"'` builds the text `set -- -Xmx64m -Xms64m "$@"` and runs it as a command. `eval` runs text as a command. The last part, `'"$@"'`, is in single quotes so the text reaches `eval` untouched, and `eval` expands it, which puts all your original arguments back after the two options, each as one word. After this line the parameters are: `-Xmx64m -Xms64m -Dorg.gradle.appname=gradlew -jar .../gradle-wrapper.jar check ...`.
- The comments warn that a newline or an unmatched quote inside those variables would break this. They are empty in this repository's normal use.

### Starting Java (line 248)

```sh
exec "$JAVACMD" "$@"
```

`exec` replaces the running shell with the program that follows, so no extra process stays waiting. `"$JAVACMD"` is the Java program (quoted in case the path has spaces) and `"$@"` is the full list built above. The command it runs is therefore `java -Xmx64m -Xms64m -Dorg.gradle.appname=gradlew -jar <folder>/gradle/wrapper/gradle-wrapper.jar check`. Because of `exec`, the exit code of `./gradlew` is exactly the exit code of Java: 0 when the build passes, 1 when it fails. The wrapper (`gradle-wrapper.md`) takes over from here.

### The file's mode and line endings

The file must have the executable permission (shown as `-rwxr-xr-x`) or `./gradlew` says "permission denied". It must also have Unix line endings. The kernel reads the shebang line up to the line break; with Windows endings the interpreter name would be `/bin/sh` followed by an invisible carriage return, and the system would report "bad interpreter". `.gitattributes` forces `eol=lf` for this file (`git.md`).

## Mistakes people make

- **Spaces around `=`.** `a = 1` runs a program named `a`. Write `a=1`.
- **Unquoted variables.** `$path` with a space inside splits into two words. This script quotes: `"$app_path"`, `"$JAVACMD"`, `"$@"`.
- **`$*` instead of `"$@"`.** `$*` merges the arguments; `"$@"` keeps each one separate. The script uses `"$@"` for the real argument list.
- **Bash-only features in an `sh` script.** Arrays and `[[ ]]` do not exist in POSIX `sh`. Gradle's script avoids them on purpose.
- **Missing `exit` after an error.** `die` ends with `exit 1`, so the script does not carry on into a failure.
- **Editing the script with a Windows editor** that saves `\r\n` endings. `.gitattributes` and `.editorconfig` (`end_of_line = lf`) guard against it.
- **Hand-editing a generated file.** The header says the script is generated by Gradle. Regenerate it with `./gradlew wrapper`.
